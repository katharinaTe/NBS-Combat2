# Methodology

This note documents the modelling choices, parameters, and assumptions behind the
NBS Combat solution so the results are auditable and the framework can be
re-pointed at the official UDM-2025 case study.

## 1. Problem statement

Retrofit an urban drainage catchment with Nature-Based Solutions (NBS) so as to,
simultaneously:

* **minimise** design-storm flooding (hydraulic performance),
* **minimise** lifecycle cost (capital + present-value operation & maintenance),
* **maximise** co-benefits (amenity, biodiversity, urban cooling, carbon).

These objectives conflict, so the solution is a **Pareto front** of non-dominated
designs rather than a single point, plus a transparent multi-criteria selection
of recommended designs.

## 2. Hydraulic model

* **Engine:** EPA-SWMM 5.2 via `pyswmm`/`swmm-toolkit` (the SWMM engine is
  embedded; no external install required).
* **Routing:** dynamic-wave (`DYNWAVE`), Horton infiltration, ponding allowed so
  node surcharge is recorded as flooding volume rather than silently lost.
* **Demonstration network** (`data/case_study/baseline.inp`, regenerated by
  `scripts/make_baseline_model.py`): 12 sub-catchments (2 ha each, 24 ha total),
  imperviousness 45–85% rising toward the dense core, draining through two
  laterals into a deliberately under-capacity trunk sewer (0.75 m) and a free
  outfall. The under-capacity trunk is what makes the retrofit problem bite.
* **KPI extraction:** cumulative node-flooding volume is summed from each node's
  SWMM flow-routing statistics (`flooding_volume`, m³); outfall peak flow is the
  maximum total inflow at the outfall over the simulation.

### Design storms

Chicago design hyetographs (2 h duration, 5 min steps, peak factor r = 0.4) are
generated for three return periods and embedded as SWMM time series:

| Storm | Return period | Depth | Baseline flooding | Role |
|---|---|---:|---:|---|
| `TS_T1`   | 1-year   | 28 mm | 0 m³     | verification (network copes) |
| `TS_T10`  | 10-year  | 48 mm | 629 m³   | optimisation (weight 0.6) |
| `TS_T100` | 100-year | 78 mm | 4,640 m³ | optimisation (weight 0.4) |

Optimisation uses the two binding storms (T10, T100); the 1-year storm is held
out for independent verification that the recommended design does not introduce
new flooding at frequent events.

## 3. NBS catalogue

Each NBS is mapped to an EPA-SWMM LID process with a validated `[LID_CONTROLS]`
parameter block (`src/nbscombat/nbs_catalog.py`). The default active palette:

| NBS | SWMM LID | Sits on | Capital | O&M | Treats upstream runoff |
|---|---|---|---:|---:|---|
| Bioretention cell / rain garden | BC | pervious land | €180/m² | €6/m²·yr | yes |
| Green roof | GR | impervious (roofs) | €220/m² | €8/m²·yr | direct rainfall only |
| Permeable pavement | PP | impervious (paving) | €120/m² | €4/m²·yr | direct rainfall only |
| Rain barrel / cistern | RB | impervious (roofs) | €90/m² | €2/m²·yr | yes |

Infiltration trenches (IT) and vegetated swales (VS) are defined and validated in
the catalogue for easy extension. Costs are order-of-magnitude planning figures
and should be replaced with the Combat's prescribed unit costs when available.

**Lifecycle cost** = capital + present value of O&M over a 20-year appraisal at a
3% discount rate.

**Co-benefit index**: each NBS carries a 0–1 score per m² for amenity,
biodiversity, cooling, and carbon; these are combined with weights
(0.30 / 0.30 / 0.25 / 0.15) and scaled by footprint. The weights are a
transparent default and are a natural place to inject stakeholder preferences.

## 4. Decision variables and feasibility

The decision vector has one entry per (sub-catchment × NBS-type) pair — 48
continuous variables in [0, 1] for the demonstration case. Decoding to physical
footprints enforces:

* **Per-type suitability ceilings** (e.g. green roofs ≤ 45% of impervious area,
  bioretention ≤ 20% of pervious land).
* **Land-availability** per sub-catchment: impervious-sited and pervious-sited
  measures are scaled so they never exceed 95% / 90% of the available area.
* **Treatment realism**: the total impervious runoff routed to LIDs in a
  sub-catchment is capped at 95%.

This guarantees every decoded design is physically realisable, so the optimiser
searches a box `[0,1]^n` without brittle hard constraints.

## 5. Optimisation

* **Algorithm:** NSGA-II (`pymoo`) — pop 60, 40 generations by default
  (configurable; `--full` uses 100 × 70). SBX crossover (η = 15) and polynomial
  mutation (η = 20).
* **Spread-seeding:** the initial population is generated with random sparsity
  and intensity per individual (rather than uniform LHS, which averages to large,
  costly designs). This populates the affordable end of the Pareto front, where
  the most decision-relevant trade-offs live.
* **Optional budget constraint:** `--budget` adds `cost ≤ budget` as a hard
  inequality constraint.

Each evaluation runs the SWMM engine for every optimisation storm (~45 ms per
storm on the demonstration network), so a default run is ~2,400 simulations in a
couple of minutes.

## 6. Decision support

From the Pareto set the framework reports three picks (`src/nbscombat/decision.py`):

* **TOPSIS** — weighted compromise across all three objectives (headline
  recommendation; weights configurable via `--weights`).
* **Knee point** — maximum-curvature point of the cost–flood trade-off; the best
  marginal value for money.
* **Budget-optimal** — cheapest design achieving a 90% flood-reduction target.

## 7. Limitations and extensions

* The demonstration network is a realistic stand-in, **not** the official Combat
  catchment; swap in the official `.inp` with `--inp`.
* Water-quality / CSO objectives are not yet modelled; SWMM supports pollutant
  build-up/wash-off and the objective vector can be extended in `problem.py`.
* Continuous (long-term) simulation for volume-capture and runoff-frequency
  metrics is a straightforward extension of the storm loop in `swmm_model.py`.
* NBS unit costs and co-benefit scores are planning-grade defaults; replace with
  the Combat's prescribed values for a competition submission.
